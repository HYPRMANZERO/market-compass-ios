# Market Compass — consented document intake and market quote refresh
Updated: 2026-11-22. Status: feature branch only until CI and owner iPhone checks.

## User-visible behaviour implemented
- iPhone Files picker allows multi-select CSV, TXT, transaction JSON and selectable-text PDF. Each selected file is parsed **locally**, individually reviewed, then owner-approved into the existing passphrase-encrypted vault. Remaining files are held only in memory during the current session. A cancelled document is skipped.
- An encrypted PDF triggers a **one-time password request after detection**, even if no password was entered before selecting it. Neither the original document nor the password is persisted, uploaded, logged or sent to Ollama. Browser-memory erasure cannot be guaranteed instantly.
- Local categories now include bank statements, credit products, payslips, invoices and receipts. Explicit payslip payment dates can anchor gross-pay, PAYE and net-pay facts; unknown dates remain unknown. Sensitive numbers/emails/phones are redacted where recognisable and must still be reviewed.
- A collapsible historical-evidence panel shows **separate** monthly figures for observed net pay from payslips, purchase receipt totals, and bank-statement debit rows. It does **not** alter Debt Plan or Spend, does not add the columns together, and warns that overlapping documents can double-count source evidence.
- On browsers exposing the File System Access directory picker (typically desktop Chromium), a user may grant read access to a **specific selected folder**. The importer inventories only name, size and modification time, discovers changed eligible files, and rechecks every five minutes **while the unlocked page remains open** or on return to it. No selected folder handle/path is saved. Parsing each discovered file still requires a separate owner action. The session-only grant stops when the importer unmounts. Browser-managed permissions may need revocation in site settings.
- iPhone Safari cannot silently enumerate folders, mailboxes or the entire device, run a persistent background filesystem watcher, or inherit desktop folder grants. On iOS the user explicitly selects files again for updates.
- The fixed client-side 90-second crypto quote block and its message were removed. Manual refresh is permitted when not already pending. Automatic polls remain every five minutes; actual provider/remote gateway quotas, 429s, authentication, source timestamps and read-only trust boundaries remain enforced. This does **not** bypass any data provider's terms or guarantee every tap produces a different quote.

## Current safety/resource boundaries
- No direct upload to HYPRBOX, GitHub or external OCR service as part of browser file import. Existing encrypted summary vault remains the same schema and origin as before.
- Original PDF parsing uses bundled PDF.js; selectable-text only. No hidden scanning of photos, DOCX/XLSX or Gmail attachments yet. Other formats require a vetted local extractor.
- The iPhone memory-safety ceiling remains 64 MiB per PDF, the extracted text processing ceiling 16 MB, and encrypted-vault summary intake is bounded to 100 files and 300 retained lines per source. The PDF page loop has no fixed page count, but very large documents still need a streaming/desktop worker. These are resource ceilings, not claims of unlimited support.
- All document-source facts remain **imported/historical/unverified**; no bank balance, current debt balance, tradeable crypto holding, or income payment is invented.
- Historical numbers are not automatically posted as ledger transactions; the owner must individually approve dates, signs and categories. A file's printed date is not assumed to be a debit date, and explicit pay dates are used only for payroll fields.

## Required before commercial onboarding or iOS release
1. **Consent UX**: separate optional grants for Files, selected folders, mail and banks; record scope, expiry, user identity, revocation and a comprehensible retention/deletion policy. Data processing under South Africa's POPIA needs an appropriate purpose, minimisation, safeguards and user rights. Avoid using device permissions as blanket consent for future unrelated processing.
2. **Native/desktop companion**: user-installed and separately authorised local folder watcher and background worker for real recurring discovery, including reauthorisation, OS permission revocation and efficient streaming of oversized PDFs. iOS Safari PWA cannot supply this.
3. **Email connectors**: per-account OAuth to a read-only provider endpoint (for example Gmail or Microsoft Graph) with least-privilege scope; only consented financial attachments/messages; clear provider provenance and token encryption. Do not reuse ChatGPT's separately connected mailbox as the app's OAuth authorisation.
4. **Bank integrations**: licensed/authorised read-only aggregators with institution-specific consent, consent renewal, refresh controls, audit, and confidence/status timestamps. Provider access failures are **unknown**, never zero. No unauthorised credential scraping or bank-login collection.
5. **Local OCR and document readers**: offline/consented extraction for scans, images, DOCX/XLSX; support per-document passwords using ephemeral entry and vetted parsers. Larger imports should stream and checkpoint safely, not remove iPhone memory limits.
6. **Document identity/deduplication**: collision-resistant source fingerprints computed locally with privacy protection and owner conflict review; preserve raw-source provenance without storing identifiers in plain text. Avoid summing overlapping bank statements, receipts and payslips as independent verified income/spend.
7. **Optional LLM review**: only owner-approved, minimised text may go to the private HYPRBOX Ollama engine over its protected gateway; deterministic parser remains the default and LLM output is a proposed classification needing human review. No client-to-Ollama public Internet path.
8. **Acceptance**: on-device iPhone Safari PWA regression for batch picker, PDF wrong/correct password, vault lock/unlock, backup/restore and reload; desktop folder-grant permission/revocation check; visual market card with provider 429; accessible mobile layout, CI, rollback and security review for both PWA variants.
